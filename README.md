# LDNDRC docs map

A standalone, static documentation site for LDNDRC. It presents the project as a
map of concepts rather than a folder of files: each node is a topic, each arrow is
a prerequisite, and every topic can build a route from the roots to itself.

The interaction model and visual language follow
[vimjoyer.com/nixmap](https://vimjoyer.com/nixmap/) — a pannable SVG map, a
side sheet for reading, and a status bar — re-implemented from the design tokens
rather than copied. No nixmap assets, CSS, mascot, or simulations are used.

## Build and run

```bash
cd docs-site
npm install
npm run build      # writes dist/
npm run serve      # builds, then serves dist/ on http://127.0.0.1:8090
```

`dist/` is the deliverable. It has no server dependency: open
`dist/index.html` directly from disk and everything works, including the
lessons, the routes, and the library. Fonts are inlined as `data:` URIs so
`file://` keeps the intended typography.

## What is where

```text
docs-site/
  content/
    graph.json          topics, domains, goals, prerequisites, verify commands
    topics/<id>.md      one lesson per topic — the authored prose
  assets/fonts/         Ubuntu Sans + JetBrains Mono (woff2)
  src/
    index.html          the app shell and SVG sprite
    theme.css           tokens, components, prose, map, sheet
    app.js              map render, pan/zoom, routes, search, progress
  build.mjs             graph validation, layout, markdown → HTML, dist emitter
  serve.mjs             generated by the build; zero-dependency static server
  dist/                 generated output, safe to delete
```

## The graph

`content/graph.json` is authoritative. Three arrays:

- `domains` — eight colour-coded groups. A topic belongs to exactly one.
- `topics` — `id`, `domain`, `title`, `summary`, `status`, `minutes`, `spine`,
  `requires`, `sources`, `glyph`, and an optional `verify` command.
- `goals` — four first-class route destinations: demo on one laptop, run a
  Gazebo session, join a host laptop, go live on a real LAN.

`requires` is the only structural edge. The build validates that every id exists,
that every topic has a markdown file, and that the prerequisite graph is acyclic.
It then computes a longest-path `rank` per topic, so a route is always a valid
teaching order.

### Routes

Selecting **Route to here** on any topic, or clicking a goal, computes the
transitive ancestor closure of the target, topologically sorts it by rank, and:

- highlights those nodes and the edges that connect consecutive steps,
- dims everything else,
- opens a numbered route rail with per-step times,
- frames the readable part of the route beside the sheet.

Progress is stored in `localStorage` under `ldndrc.docs.done`. Completed steps are
marked with a check but stay in the route, so the path is never silently
rewritten.

### Writing a lesson

`content/topics/<id>.md` is plain Markdown. The build:

- strips a leading `# Heading` (the sheet supplies the title),
- highlights fenced code with highlight.js,
- turns `[[other-topic-id]]` into a link,
- appends the `verify` command from the graph as a card,
- appends source links into the library.

Keep the prose specific. The map is the guided path; the library is the archive
of every raw document in the repository, rendered verbatim.

## Status vocabulary

| Status | Meaning |
|---|---|
| `shipped` | Built and verified on real machines |
| `partial` | Working in pieces; the remaining work is named |
| `designed` | Specified, not built |

The map should never claim more than the checkpoints do. When the two disagree,
the checkpoints win.

## Keyboard and pointer

- Drag to pan, scroll to zoom, `Fit` to reset.
- `⌘K` / `Ctrl-K` or `/` opens search.
- `Esc` closes the sheet or the search palette.
- Legend chips filter by domain without changing the route state.

## Design notes

- Palette: Gruvbox dark (`#1d2021` background, `#fbf1c7` text) with one accent
  per domain.
- Shape: squircles, hard offset shadows instead of borders, tactile buttons.
- Type: Ubuntu Sans for prose, JetBrains Mono for labels, code, and status.
- No `fetch()` at runtime — the graph and lesson payloads are injected as
  `<script>` globals, which is what makes `file://` work.

## Contributing

Read [`../CONTRIBUTING.md`](../CONTRIBUTING.md) for the project rules, verification
matrix, and review checklist. For the site specifically:

1. Add or edit `content/topics/<id>.md`, and the matching node in `content/graph.json`.
2. Run `npm run build`. It validates every prerequisite, source file, and cycle.
3. Check your topic with **Route to here**, in both the sheet and `d/<id>.html`.

The graph is the single source of truth. If a lesson and the graph disagree, fix one
of them in the same commit.

## Standalone hosting

This repository is the independently hostable LDNDRC documentation site. It is
separate from the main LDNDRC repository and can be deployed by serving `dist/` as
static files.

```bash
npm install
npm run build
npm run serve
```

The generated site is also usable directly from `dist/index.html` via `file://`.
The `sources/` directory contains the source documents used to render the Library.
To build against another checkout, set `LDNDRC_SOURCE_ROOT` before running the build.
