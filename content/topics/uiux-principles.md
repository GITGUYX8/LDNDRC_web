The student UI deliberately rejects the floating-window "cockpit" desktop metaphor. Students are here to learn ROS, not to arrange windows.

## Five principles

1. **Focus over window management.** One active tool fills the stage; switching is instant and keeps the others alive.
2. **Split view is a mode, not freeform drag.** Exactly three layouts: Code, Sim, Code | Sim.
3. **Status is ambient.** Session state lives in the top bar on every screen, not on a polling page.
4. **Desktop is an escape hatch.** It opens in its own tab, as a secondary action.
5. **Light-on-dark mission control.** Warm, high contrast, built for long sessions.

## The test for any new screen

Does it answer *where am I*, *is my workspace ready*, and *what can I do now*? If a screen answers only two, it is not finished.

## Check it yourself

Open the launch screen and count the primary actions. There should be exactly one.
